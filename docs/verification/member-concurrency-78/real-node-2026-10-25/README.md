# 实际 Node 成员模式：授权模型三轮对话

使用此前授权的 Magpie → WorkBuddy 配置，通过实际产品 HTTP 创建两位 Dot 和群聊，
启用 `member-inbox-v1` 与有界 Node 并发。三轮主讨论在同一个群、同一对持久
Pi Session 中通过；第一轮还包含一次预先设计的中途用户更正。模型输出未经替换，
synthetic 请求为零；这份记录是 API 与实际推理验收，不是 Chrome 或 Cloudflare 验收。

| 主讨论 | 实际行为                                                               | 两位 Dot 的最终总预算 / 累计已用 / 剩余 | 实际请求 |
| ------ | ---------------------------------------------------------------------- | --------------------------------------- | -------: |
| 1      | Developer 独立检查时实际询问 Reviewer；Reviewer 请求在途时取消印刷支出 | 310 / 88 / 222                          |        6 |
| 2      | 明确点名两位；沿用最新状态，增加支出 23                                | 310 / 111 / 199                         |        2 |
| 3      | 重启隔离 Node 后，沿用支出并将总预算减少 17                            | 293 / 111 / 182                         |        2 |

项目唯一标识和负责人在两位回复中逐项核对。第一轮原问题/回复有真实原生 input、
Submission、Task 与 `in_reply_to`；更正后返回的同伴结论被 Developer 实际使用。
后两轮明确点名两位，核对各自的上下文连续性，不强迫无必要的同伴 RPC 或轮流顺序。
创建、设置、快照与重启没有额外调用。完成后等待并核对没有迟到回答；第三轮前
重启保持前两轮用户/Bot 消息和两个 Session，未自行推理。

三轮分别记录 6、2、2 次请求，共 10 次，已报告及产品记账均为 60,407 token。
实际 HTTP 请求重叠峰值均为二；这不是供应商 GPU 执行证明或普遍性能结论。
这些结论来自 [完整记录](api-three-turns.json)，并保留真实回答、原生关联与用量。

## 原始比较仍有失败

同一次脚本随后运行旧 `relay-v1 / serial-v1` 对照。其第一轮原生 Run 完成，
共 3 次请求；Reviewer 生成时用户取消印刷费，但其冻结输入没有该更正，
随后仍回复 102/208。Developer 的最后汇总读取了更正，回复 88/222。
脚本因“两位均应给出最新数值”的质量检查失败退出，没有把整体比较改成通过。

因此 `member_api_three_turns_passed=true`，但 `combined_comparison_passed=false`，
旧模式后两轮未完成对照。第一轮新模式 6 次请求、旧模式 3 次，不能只凭并发
宣称更省钱或更快；也没有改写旧策略的冻结输入来迁就验收。
旧模式快照、实际回复和请求区间也保留在记录中。

[摘要](summary.json) 按同一公式给出首轮实际请求数、已报告 token、HTTP 区间跨度、
两位成员最新回答的正确数和完全相同的同作者输出数。比较包含协议、上下文和调度
差异，不能把这些结果单独归因于并发，也不把 HTTP 区间当作真实 GPU 计算时间。

## 验收工具修复与失败历史

初次实际调用的结果与用量已提交，但观测代理将 SDK 在 SSE `[DONE]` 后关闭
HTTP 的正常清理标成中止。使用实际 OpenAI SDK 复现后，只在 HTTP 200、真实
finish reason 和 `[DONE]` 均已收到时区分这种清理；物理取消仍记录。
8 项回归通过，包含正文中断、只有 finish reason、只有 `[DONE]` 三个拒绝反例。

后续一次用例只点名 Developer，却要求两位贡献，已改为后两轮明确点名两位。
另一次把项目标识中的排版空格当成身份改变，现去除空白后仍严格核对完整随机
标识、负责人和全部金额；原数据中改变一个标识字符仍被拒绝。
这些失败记录仍保留在本机，没有用额外纠错提示挽救一个已经失败的三轮用例。
本次记录对应源码提交 `9769591`，不是对后续脚本版本的自动背书。
